## 2. Foundational Prompt Engineering Logs

### 2.1 Prompt Log 1: IEEE 830 Functional Requirements Extraction
- **Prompt Intent:** Generate structured functional requirements adhering to IEEE 830 standard for a civic grievance system with geotagging.
- **Engineered Prompt:**
  ```text
  Role: Lead Systems Analyst & Requirements Engineer.
  Task: Formulate the System Requirements Specification (SRS) for "CivicLens",
        a municipal complaint portal for urban local bodies.
  Constraints:
  1. Adhere to IEEE 830 functional and non-functional requirement standards.
  2. Core features: Geotagged complaint filing, Leaflet interactive map,
     automated duplicate complaint clustering, automated department routing,
     citizen public tracking, and municipal staff triage.
  3. Formulate Gherkin Given-When-Then acceptance criteria for each user story.
  4. Ensure ethical safeguards: Non-destructive duplicate linking, privacy protection
     for citizen residential coordinates.
  Format: GitHub Flavored Markdown with mathematical formulas for spatial/textual engines.
  ```
- **AI Output Highlights:**
  - Synthesized FR-1 through FR-9 and NFR-1 through NFR-6.
  - Formulated the dual-stage Haversine + TF-IDF algorithmic framework.
- **Human Review & Corrections:**
  - *Identified Gap:* AI omitted reverse-geocoding fallback when offline.
  - *Action Taken:* Added FR-3 requiring human-readable neighborhood/locality address resolution with graceful fallback to formatted coordinates.

### 2.2 Prompt Log 2: Dual-Stage Duplicate Clustering Specification
- **Prompt Intent:** Specify the mathematical and algorithmic pipeline for spatial-textual duplicate complaint detection.
- **Engineered Prompt:**
  ```text
  Role: Senior Data Scientist & Backend Algorithm Architect.
  Task: Design the duplicate complaint detection specification for CivicLens.
  Mathematical Requirements:
  1. Stage 1 (Spatial Filter): Haversine distance formula with Earth radius R = 6,371,000 meters.
     Distance threshold: D_thresh = 75 meters.
  2. Stage 2 (Textual Filter): Tokenization, stopword stripping, suffix stemming,
     Term Frequency (TF) cosine vector calculation, and Jaccard token overlap index.
  3. Formula: Hybrid Similarity = 0.8 * Cosine + 0.2 * Jaccard.
  4. Threshold: Flag as duplicate if Distance <= 75m AND Hybrid Similarity >= 0.60.
  5. Explainability: Return list of matching keywords that triggered the similarity match.
  ```
- **Human Review & Corrections:**
  - *Identified Gap:* AI initially suggested computing TF-IDF across the entire database dynamically on every request, which would cause $O(N)$ re-indexing lag on high-volume municipal intake.
  - *Action Taken:* Constrained textual similarity calculation strictly to candidates that have *already passed* Stage 1 Haversine spatial proximity ($D \le 75\text{m}$), bounding candidates to typically $< 10$ items.
