## 1. Executive Summary
This document provides an academic comparison of four candidate software engineering process models evaluated for the CivicLens municipal portal:
1. **Classical Waterfall Model**
2. **Boehm's Spiral Model**
3. **Standard Agile Scrum**
4. **AI-Augmented Agile Methodology (Selected)**

The comparative evaluation demonstrates why the AI-Augmented Agile approach is uniquely qualified to deliver CivicLens given the rapid iteration required for machine learning heuristics (geospatial distance clustering and NLP text similarity), frequent stakeholder feedback, and dual-mode resilient architecture.

## 3. Detailed Justification for CivicLens

### 3.1 Why Waterfall Was Rejected
1. **Algorithmic Uncertainty:** Duplicate complaint detection requires balancing Haversine spatial radius thresholds ($D \le 75\text{m}$) with TF-IDF cosine similarity ($\ge 0.65$). In Waterfall, fixing these hyperparameters upfront without empirical experimentation leads to catastrophic false positives (merging different complaints) or false negatives (duplicate explosion).
2. **Delayed Validation:** Leaflet map interaction and GPS mobile geocoding require tactile browser interaction. Deferring UI and map rendering to the final development phase would leave fatal usability bugs undiscovered until late in the lifecycle.

### 3.2 Why Spiral Was Deemed Suboptimal
While Spiral excels at risk analysis, its administrative overhead (formal risk management milestones, repeated formal reviews) is disproportionately heavy for a modern full-stack web application. The primary risks in CivicLens are code correctness and algorithmic edge cases, which are better mitigated by automated test suites than bureaucratic milestone reviews.

### 3.3 Why AI-Augmented Agile Was Selected
1. **Iterative Heuristic Tuning:** Agile sprints allow tuning spatial and NLP thresholds based on concrete test suites (e.g., verifying that paraphrased grievances within $75\text{m}$ cluster while distinct issues at $10\text{m}$ do not).
2. **AI Tool Velocity:** Incorporating AI coding tools (Claude, GitHub Copilot) alongside strict human architectural review accelerated boilerplate development (Mongoose schemas, Express controllers, Leaflet hooks) by an estimated $40\%$, leaving more time for verification.
3. **Safety & Verification Alignment:** AI-generated artifacts are never accepted blindly. Each sprint applies human-in-the-loop review, automated Jest test runs (84.25% line coverage), and headless Selenium E2E execution.
