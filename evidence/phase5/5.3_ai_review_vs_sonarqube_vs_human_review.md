## 3. Concrete Case Study: The Spatial-Textual Duplicate Filter Review

```
========================================================================================
CASE STUDY: REVIEWING `backend/services/ai/duplicateDetectorService.js`
========================================================================================

1. What SonarQube Detected:
   - Code Smell: Variable `candidate` declared but reassigned in inner scope (shadowing).
   - Maintainability: Cognitive complexity score was 16 (exceeded threshold of 15).
   - Security: Recommends ensuring distance threshold is a finite positive integer.

2. What AI-Assisted Review Detected:
   - Boundary Bug: Noted that if `coordinates` contains `NaN`, Haversine function returns `NaN`
     without throwing an error, causing `NaN <= 75` to evaluate to `false` silently.
   - Proposed Fix: Add `isValidCoordinates([lon, lat])` input validation guard.

3. What Human Peer Review Detected:
   - Domain Flaw: AI suggested silently discarding duplicate complaints to save DB rows.
     Human engineer rejected this, mandating non-destructive clustering where child tickets
     increment master `duplicateCount` and elevate municipal urgency.
========================================================================================
Synthesis: The three review paradigms are complementary. SonarQube enforces hygiene;
AI brainstorms edge cases; Human engineers guarantee domain correctness and ethical safety.
========================================================================================
```
