## 2. Responsible-AI Five-Dimension Governance Checklist

### Dimension 1: Algorithmic Fairness & Bias Mitigation
- [x] **Item 1.1 [Digital Divide Protection]:** The triage engine does NOT prioritize repairs based purely on raw complaint volume or density, preventing privileged wards with higher smartphone penetration from monopolizing municipal budgets.
- [x] **Item 1.2 [Hazard Severity Decoupling]:** Priority (`HIGH`, `URGENT`) is driven by physical danger (e.g. open high-voltage transformers, contaminated water) rather than ticket density.
- [x] **Item 1.3 [Non-Destructive Clustering]:** Incoming duplicate grievances are preserved as linked child tickets rather than deleted, guaranteeing every citizen's report is recorded.
- [x] **Item 1.4 [Multilingual & Slang Vocabulary]:** NLP feature dictionaries include informal and colloquial Indian civic terms (`crater`, `manhole`, `waterlogging`, `kuchha road`) to accommodate diverse literacy backgrounds.

### Dimension 2: Citizen Privacy & Data Protection (GDPR / DPDP Act)
- [x] **Item 2.1 [Residential Geotag Redaction]:** Public map endpoints (`GET /api/complaints/map`) suppress citizen names, phone numbers, and exact residential addresses, preventing residential profiling.
- [x] **Item 2.2 [Tiered Geographic Access]:** Only authenticated municipal staff (`role === 'staff'`) have access to precise coordinates for field work order dispatch.
- [x] **Item 2.3 [Anonymous Filing Option]:** Citizens can report public street defects anonymously without submitting mandatory personal phone numbers or ID cards.
- [x] **Item 2.4 [Right to Erasure / Anonymization]:** Account deletion requests unlink citizen identifiers from submitted tickets, anonymizing user references while preserving civic defect history.

### Dimension 3: Intellectual Property, Licensing & Open-Source Hygiene
- [x] **Item 3.1 [Permissive Open-Source Licensing]:** CivicLens is released under the **MIT License**.
- [x] **Item 3.2 [Third-Party Dependency Audit]:** All npm packages (Express, React, Leaflet, Mongoose, bcryptjs, jsonwebtoken) operate under permissive licenses (MIT / Apache 2.0 / BSD).
- [x] **Item 3.3 [Clean-Room Code Synthesis]:** AI prompt templates explicitly required CommonJS/ES6 standard code synthesis without copying proprietary or copyleft (GPL v3) source code.

### Dimension 4: Transparency & Explainability (XAI)
- [x] **Item 4.1 [Keyword Feature Attribution]:** Department routing suggestions display contributing keywords (`#pothol`, `#asphalt`) and confidence scores.
- [x] **Item 4.2 [Alternative Category Probabilities]:** Returns runner-up department predictions so officers can review close classification boundaries.
- [x] **Item 4.3 [Dual-Factor Duplicate Attribution]:** Clustered complaints show both spatial distance (meters) and text similarity score (percentage) justifying why tickets were merged.
- [x] **Item 4.4 [Public Tracking Transparency]:** Citizens can inspect their ticket's audit progression at any time using their unique reference ID (`CL-2026-XXXXXX`).

### Dimension 5: Accountability & Human-in-the-Loop Governance
- [x] **Item 5.1 [Human Override Mandate]:** Automated AI classifications are advisory only; municipal officers have unilateral authority to reassign departments or split clusters.
- [x] **Item 5.2 [Immutable Audit Trail]:** Every lifecycle modification (`SUBMITTED` $\rightarrow$ `ASSIGNED` $\rightarrow$ `IN_PROGRESS` $\rightarrow$ `RESOLVED`) permanently logs officer ID, timestamp, and mandatory remarks.
- [x] **Item 5.3 [Mandatory Resolution Remarks]:** The system forbids closing a complaint without explicit, human-authored resolution notes.
