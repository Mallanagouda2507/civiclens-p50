## 1. Executive Summary
Municipal grievance platforms capture sensitive citizen telemetry: precise geographic coordinates, personal contact details, residential addresses, and civic dispute descriptions.

CivicLens was architected to comply with international data privacy standards, specifically the **EU General Data Protection Regulation (GDPR)** and India's **Digital Personal Data Protection (DPDP) Act 2023**. This document outlines the technical safeguards enforced to protect citizen privacy.

---

## 2. Regulatory Alignment Matrix (GDPR / DPDP Act)

| Regulatory Principle | Statutory Requirement | CivicLens Technical Implementation |
|---|---|---|
| **Data Minimization (GDPR Art. 5c / DPDP Sec. 6)** | Collect only personal data necessary for municipal remediation. | Citizens can file complaints without providing mandatory telephone numbers or national ID cards; anonymous submissions supported. |
| **Storage Limitation (GDPR Art. 5e / DPDP Sec. 8)** | Retain personal identifiers only as long as required for remediation. | User profiles decoupled from public complaint feeds; resolved complaints retain civic defect history while archiving citizen contact logs. |
| **Purpose Limitation (GDPR Art. 5b)** | Personal data must not be repurposed for unauthorized tracking. | Geolocation coordinates captured exclusively for dispatching municipal field engineers, never sold or shared with commercial ad-networks. |
| **Right to Erasure / Deletion (GDPR Art. 17 / DPDP Sec. 12)** | Citizen right to withdraw consent and request personal data deletion. | Database schema supports unlinking user accounts from submitted tickets; replaces user ID with `ANONYMIZED_CITIZEN`. |
| **Integrity & Confidentiality (GDPR Art. 32)** | Protection against unauthorized access or disclosure. | Passwords hashed using bcrypt (10 rounds); JWT HS256 tokens; TLS/HTTPS transport encryption enforced in Docker Nginx config. |

## 3. Geotag Governance & Residential Coordinate Protection

### 3.1 The Residential Privacy Threat
When a citizen reports a domestic infrastructure issue (e.g., residential sewage backup, low tap water pressure, or a localized electrical short circuit), their exact GPS pin could pinpoint their private front door on a public map. This presents a stalking, harassment, or burglary profiling risk if exposed publicly.

### 3.2 Tiered Spatial Access Model
CivicLens enforces a **Two-Tier Spatial Telemetry Architecture**:

```
[ Incoming Complaint with Exact GPS Coordinates: 12.978412, 77.641289 ]
                             │
                             ▼
     ┌───────────────────────────────────────────────┐
     │          ROLE-BASED SPATIAL FILTER            │
     └───────────────────────┬───────────────────────┘
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
   [ PUBLIC MAP FEED ]               [ STAFF TRIAGE FEED ]
   • GET /api/complaints/map         • GET /api/complaints
   • Citizen PII Redacted            • Full Exact GPS Coordinates
   • Exact address truncated         • Full Residential Address
   • Pin rendered at ward level      • Reporter Contact for Dispatch
```

1. **Public View (`GET /api/complaints/map`):**
   - Citizen phone numbers, personal email addresses, and full names are completely excluded from the JSON output.
   - Only civic metadata (tracking ID, title, department, status, duplicate count) is publicly visible.
2. **Staff Triage View (`GET /api/complaints`):**
   - Restricted strictly to authenticated municipal officers with role `staff` or `admin`.
   - Displays full geographic details and reporter phone numbers so field repair crews can coordinate repairs.

## 4. Immutable Audit Trail for Governance & Accountability

To eliminate bribery, tampering, or silent deletion of inconvenient municipal complaints, CivicLens enforces an append-only audit trail on every ticket:

```javascript
// Audit Record Schema in backend/models/Complaint.js
auditLog: [
  {
    changedBy: { type: ObjectId, ref: 'User' },
    previousStatus: String,
    newStatus: String,
    remarks: String,
    timestamp: { type: Date, default: Date.now }
  }
]
```

- Every status modification (`SUBMITTED` $\rightarrow$ `ASSIGNED` $\rightarrow$ `IN_PROGRESS` $\rightarrow$ `RESOLVED`) permanently records the identity of the officer, timestamp, and mandatory remarks.
- Citizens can publicly verify this audit history at any time using their tracking reference ID (`CL-2026-XXXXXX`).
