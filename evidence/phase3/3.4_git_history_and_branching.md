## 4. Merge Conflict Scenario & Resolution Evidence

During the concurrent integration of `feature/ai-duplicate-engine` and `feature/complaints-lifecycle`, a merge conflict occurred in `backend/controllers/complaintController.js` regarding the duplicate cluster linkage schema.

### 4.1 Git Conflict Marker
```javascript
<<<<<<< HEAD (feature/complaints-lifecycle)
// Developer A: Simplified duplicate flag
const isDuplicate = req.body.isDuplicate || false;
const duplicateMasterId = req.body.masterId || null;
=======
// Developer B: Automated AI clustering result
const { isDuplicate, masterComplaintId, similarityScore } = 
  await duplicateDetectorService.findDuplicateInCandidates(newComplaint, nearbyOpenComplaints);
>>>>>>> feature/ai-duplicate-engine
```

### 4.2 Merge Resolution Applied
- **Conflict Analysis:** Developer A assumed manual client-side flagging, whereas Developer B implemented automated server-side clustering using the AI engine.
- **Resolution:** Retained Developer B's automated AI clustering pipeline while incorporating Developer A's fallback tracking assignment.
- **Resolved Code:**
```javascript
// Harmonized Resolution: Server-side AI clustering with automated master ticket linkage
const clusterResult = await duplicateDetectorService.findDuplicateInCandidates(
  { title, description, location: { coordinates: [lon, lat] } },
  nearbyOpenComplaints
);

const isDuplicate = clusterResult.isDuplicate;
const masterComplaintId = clusterResult.isDuplicate ? clusterResult.masterTicket._id : null;
const duplicateSimilarityScore = clusterResult.similarityScore || 0;
```
