## 2. Chronological Engineering Log

### Milestone 1: Repository Initialization & Architectural Scaffolding
- **Date:** October 2026 (Sprint 1, Days 1–3)
- **Objective:** Establish modular monorepo structure with independent backend (`backend/`) and frontend (`frontend/`) workspaces.
- **Actions:**
  - Initialized Git repository; configured `.gitignore` excluding `node_modules`, `.env`, and build artifacts.
  - Authored foundational package manifests and established directory conventions: `controllers/`, `routes/`, `services/`, `middleware/`, and `tests/`.
- **Engineering Reflection:** Keeping the backend and frontend workspaces decoupled allows independent dependency management while enabling a unified root build script.

### Milestone 2: Dual-Mode Persistence & Identity Subsystem
- **Date:** October 2026 (Sprint 1, Days 4–10)
- **Objective:** Implement user authentication (JWT + bcrypt) and a resilient persistence layer that functions without external MongoDB dependencies.
- **Actions:**
  - Created `backend/services/dataStore.js` with dynamic connection checking: checks `mongoose.connection.readyState`. If disconnected, executes queries against an in-memory repository implementing identical async query interfaces.
  - Implemented `authController.js` with 10 salt rounds bcrypt hashing, JWT issuance with 24-hour expiry, and role-based gating middleware (`protect`, `authorize`).
- **Blocker & Resolution:** Windows socket binding permissions blocked initial Supertest executions. *Resolution:* Configured execution environment to permit local loopback socket binding on Windows.

### Milestone 3: Mathematical Geospatial & NLP Duplicate Detection Engine
- **Date:** October 2026 (Sprint 2, Days 11–18)
- **Objective:** Implement great-circle geodesic math and text similarity algorithms in pure Node.js.
- **Actions:**
  - Built `geoSpatialService.js` implementing spherical trigonometry (Haversine formula, $R = 6,371,000\text{m}$).
  - Built `textSimilarityService.js` with tokenization, stopword removal, suffix stemming, and hybrid Cosine (80%) + Jaccard (20%) scoring.
  - Built `departmentClassifierService.js` mapping civic grievances to 6 departments: `ROADS`, `WATER_SUPPLY`, `SANITATION`, `ELECTRICITY`, `HEALTH_SAFETY`, and `PARKS`.
- **Architectural Pivot:** AI initially generated a 2-document IDF calculation that zeroed out similarity when both complaints contained the target word. Refactored the math to use normalized Term Frequency (TF) cosine angles, elevating valid duplicates to $0.70-0.85$ while keeping unrelated complaints $< 0.20$.

### Milestone 4: Complaint REST API, Lifecycle State Machine & Analytics
- **Date:** November 2026 (Sprint 3, Days 19–26)
- **Objective:** Complete full CRUD and lifecycle management for complaints.
- **Actions:**
  - Implemented `complaintController.js` generating human-readable tracking IDs (`CL-2026-XXXXXX`), reverse geocoding coordinates to locality names, and recording an immutable append-only audit trail on every status transition.
  - Implemented municipal executive analytics (`analyticsController.js`) aggregating backlog, resolution averages, and department distribution.
  - Authored realistic Bangalore civic seed generator (`backend/scripts/seed.js`).

### Milestone 5: React UI, Leaflet GIS Maps & Full-Stack Integration
- **Date:** November 2026 (Sprint 4, Days 27–34)
- **Objective:** Build full-featured React frontend with interactive Leaflet GIS maps.
- **Actions:**
  - Built `SubmitComplaintPage.jsx` with Leaflet pin-drop coordinate picker, live duplicate warning banner, and reverse geocoding display.
  - Built `CivicMapPage.jsx` rendering color-coded pins (Red: Open, Amber: In Progress, Green: Resolved) and popups with tracking references.
  - Built `StaffTriagePage.jsx` allowing department filtering, status updates, and resolution notes entry.
- **Blocker & Resolution:** Vite React production build failed due to an unescaped LaTeX token `$\le 75\text{m}$` where JSX interpreted `{m}` as an undefined variable. *Resolution:* Replaced with HTML entity `&le; 75 meters` and successfully rebuilt bundle.

### Milestone 6: Test Coverage Uplift, Selenium E2E & DevOps Pipelines
- **Date:** November 2026 (Sprint 4, Days 35–40)
- **Objective:** Uplift test coverage past 80%, add headless Selenium E2E suite, configure Jenkinsfile and SonarQube scanner.
- **Actions:**
  - Expanded test suites (`backend/tests/aiRoutes.test.js`, `complaints.test.js`), achieving **84.25% line coverage** across 70 passing tests.
  - Implemented headless Selenium test runner (`tests/selenium/runSeleniumTests.js`) successfully validating 5/5 user actions against live application.
  - Added declarative `Jenkinsfile` with 7 stages and `sonar-project.properties` with execution logs recorded.
