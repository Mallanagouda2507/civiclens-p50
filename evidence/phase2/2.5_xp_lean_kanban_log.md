## 2. Extreme Programming (XP) Practices Log

| XP Practice | Implementation in CivicLens | Verification Artifact |
|---|---|---|
| **AI Pair Programming** | The engineer acted as the Driver/Architect while AI developer tools (Copilot, Claude) acted as the Navigator/Syntax Synthesizer, generating boilerplate and suggesting edge-case tests. | Evidence 1.5 & 3.2 (Prompt logs and human review records). |
| **Test-Driven Development (TDD)** | Algorithmic services (`geoSpatialService.js`, `textSimilarityService.js`) had unit tests authored alongside initial specs to ensure boundary compliance before endpoint integration. | 70 passing Jest unit/integration tests (`tests/aiEngine.test.js`). |
| **Continuous Integration (CI)** | Every commit to the repository is automatically validated by an automated test pipeline running linting, build, and test suites. | `.github/workflows/ci.yml` & declarative `Jenkinsfile`. |
| **Refactoring** | Active refactoring of AI-generated code: replaced faulty IDF formula with normalized TF cosine angles; replaced planar Euclidean distance with geodesic Haversine math. | Commits `d707dab` and `b03ecfa`. |
| **Simple Design (YAGNI)** | Avoided microservices and heavy vector databases. Built a single, highly cohesive monolithic Express service with clean modular boundaries. | Unified Node.js backend executing in $< 20\text{s}$ for 70 tests. |
| **Coding Standards** | Strict linting, ES6 modular syntax, camelCase variables, UPPER_CASE constants, and RFC-7807 error responses. | Automated static linting in CI pipeline. |

## 3. Lean Software Development Principles Log

| Lean Principle | CivicLens Engineering Application | Concrete Outcome |
|---|---|---|
| **1. Eliminate Waste (Muda)** | Avoided premature optimization (e.g., fine-tuning BERT transformers). Replaced with lightweight TF-IDF and keyword feature attribution. | Saved ~60% development and training time; reduced RAM footprint from ~2GB to <150MB. |
| **2. Build Quality In (Jidoka)** | Fail-fast validation middleware on all API routes: missing coordinates, malformed JSON, and unauthorized roles immediately rejected with informative HTTP codes. | 100% of invalid payloads rejected before hitting business logic. |
| **3. Create Knowledge** | Maintained comprehensive prompt engineering libraries, architectural diffs, and living academic documentation. | Evidence archives 1.1 through 5.6. |
| **4. Defer Commitment** | Abstracted the persistence layer through `dataStore.js` so database engine selection (local vs MongoDB Atlas vs In-Memory) could be switched via environment config. | Zero dependency blockers for offline academic evaluation. |
| **5. Deliver Fast** | Kept iteration cycles strictly to 2 weeks, delivering runnable vertical slices every sprint. | Complete functional application completed in 4 sprints. |
| **6. Respect People** | Provided transparent Explainable AI (XAI) keywords to municipal workers rather than unchallengeable black-box machine predictions. | Improved user trust and administrative adoption. |
| **7. Optimize the Whole** | Balanced spatial proximity, textual similarity, and citizen privacy in a holistic end-to-end user journey. | Complete municipal complaint lifecycle from intake to resolution. |

## 4. Kanban Workflow & Work-In-Progress (WIP) Limits

CivicLens utilized a Kanban board to visualize flow and constrain Work-In-Progress (WIP) across four key pipeline columns:

```
┌─────────────────┬─────────────────┬─────────────────┬─────────────────┐
│     TO DO       │   IN PROGRESS   │   CODE REVIEW   │      DONE       │
│  (WIP Limit: 8) │  (WIP Limit: 3) │  (WIP Limit: 2) │  (WIP Limit: ∞) │
├─────────────────┼─────────────────┼─────────────────┼─────────────────┤
│ [US-08: Report] │ [US-04: Leaflet]│ [US-03: Picker] │ [US-01: Auth]   │
│                 │ [US-06: NLP]    │                 │ [US-02: RBAC]   │
│                 │                 │                 │ [US-05: Cluster]│
│                 │                 │                 │ [US-07: Track]  │
└─────────────────┴─────────────────┴─────────────────┴─────────────────┘
```

- **WIP Limit Rationale:**
  - `IN PROGRESS (Limit = 3)`: Prevented developers from multitasking across GIS, Auth, and NLP simultaneously.
  - `CODE REVIEW (Limit = 2)`: Prevented completed features from piling up without thorough human code inspection and test execution.
